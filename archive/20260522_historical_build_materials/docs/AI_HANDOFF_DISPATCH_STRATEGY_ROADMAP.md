# AI 交接文档：调度策略与算法路线图讨论

本文用于开启一个新的 ChatGPT 对话，继续讨论“绿电直连、源网荷储、微电网、离网风光储柴”的全年逐时调度策略与算法路线图。本文只描述当前项目状态、已形成的算法边界和下一阶段应讨论的问题，不是开发日报，也不是已实现功能清单之外的承诺。

## 1. 项目当前定位

本项目当前可以理解为一个并网型绿电直连 / 风光储多方案枚举测算软件的工程底座。V0.1 已经完成并网型风电、光伏、储能容量组合的批量枚举、逐小时技术仿真、政策指标汇总、结果导出和基础 UI。当前产品方向已经从“把所有枚举方案表格展示给用户”转向“绿电直连 / 微电网项目方案策划与推荐平台”。

当前阶段的重点不是继续打磨 UI、图表或完整经济性模型，而是把逐时调度策略、能量台账、算法边界和未来扩展路径说清楚。后续系统可能扩展到源网荷储、弱网、并网柴发备用、微电网、离网风光储柴等场景，因此需要先确定不同场景不应混用同一套调度逻辑。

简言之：V0.1/V0.2 是并网无柴发风光储技术仿真的稳定基线；下一阶段要讨论的是如何在不推翻基线的前提下，分场景、分策略、分阶段扩展调度算法。

## 2. 当前 V0.2 已完成的底层稳定化工作

当前代码中已经完成了一轮保护性底层稳定化：

| 事项 | 当前状态 |

| 默认行为 | 不传 strategy 时仍使用 `GRID_CONNECTED_RENEWABLE_FIRST_GREEDY` |
| 结果记录 | `summary["dispatch_strategy"]` 记录实际策略 |
| 小时台账 | `hourly_detail` DataFrame 已明确为 V0.1 的 `HourlyEnergyLedger` 物理实现 |
| 字段常量 | `HOURLY_LEDGER_COLUMNS` 为显式台账字段；`HOURLY_COLUMNS` 保持兼容别名 |

## 3. 当前默认调度策略的业务含义

当前唯一实现的调度策略是：

```text
GRID_CONNECTED_RENEWABLE_FIRST_GREEDY
```

它适用于并网绿电直连 / 并网型风光储技术测算，是政策口径下的 renewable-first greedy 策略。它不是经济最优调度，不是 HOMER 式完整微电网调度，也不是离网风光储柴调度。

当前逻辑大致为：

1. 新能源优先供负荷；
2. 富余新能源优先给储能充电；
3. 储能充不下的富余新能源尝试上网；
4. 超出上网比例、上网功率或不允许上网的部分弃电；
5. 新能源不足时，储能优先放电供负荷；
6. 储能仍不足时，电网下网补足；
7. 若电网交换功率限制导致仍不能满足负荷，则记录缺口。

当前储能只允许由富余新能源充电，不允许电网充电，不允许同小时充放电，不允许储能放电上网。因此当前储能放电可以计入新能源自发自用口径。

## 4. 已经形成的关键共识

- 当前 V0.1/V0.2 并网无柴发模型不推翻，继续作为第一个明确命名的调度策略。
- 当前算法应被视为第一个显式策略，而不是未来所有场景的唯一算法。
- 技术仿真先生成 `hourly_detail` 事实台账；政策、经济、图表、报告、推荐排序应读取该台账和 summary。
- 上层模块不应重新计算 SOC、弃电、上网、下网、储能充放电等核心调度结果。
- 经济性评价不能反向改变已有调度结果。如果未来需要经济最优调度，应新增新的 `DispatchStrategy`，而不是让 `EconomyEvaluator` 悄悄修改技术仿真。
- 当前储能只由富余新能源充电，所以储能放电可计入绿电自用。
- 如果未来允许电网或柴油机给储能充电，必须增加储能电量来源分账，否则会污染绿电指标。
- 并网绿电直连、并网柴发备用、弱网系统、离网风光储柴不能混用同一套调度逻辑。
- 离网系统需要单独讨论 Load Following、Cycle Charging、Combined Dispatch、储能成网、柴发成网、备用容量、缺供可靠性等问题。

- Cycle Charging；
- Load Following；

## 6. 下一阶段真正要讨论的问题

下一阶段应讨论算法路线图，而不是马上写代码。建议围绕以下四层展开。

### 6.1 场景分层

| 场景 | 需要单独澄清的问题 |
|---|---|
| 并网绿电直连 | 是否继续使用 renewable-first greedy；上网比例、电网交换限制如何处理 |
| 并网 + 柴发备用 | 柴发是在电网之后兜底，还是可参与经济运行 |
| 弱网 / 限电 / 电网受限 | 电网可用性、下网功率、上网功率、缺供如何表达 |
| 离网储能成网型 | 储能承担成网与短时平衡，柴油是否只兜底 |
| 离网柴发成网型 | 柴发最小稳定出力、储能吸收余电、启停逻辑是否必须建模 |
| 高级经济调度 / 优化调度 | 是否引入预测、分时电价、燃油成本、MILP 或启发式优化 |

### 6.2 调度目标分层

不同场景的目标不一样，不能只用一个“最优”概念覆盖：

- 政策合规；
- 最大化新能源自发自用；
- 最小化下网；
- 控制上网比例；
- 保证供电可靠性；
- 最小化柴油消耗；
- 最小化全寿命周期成本；
- 最小化缺供；
- 兼顾储能寿命。

需要明确哪些目标是硬约束，哪些只是排序指标。例如离网场景中“缺供为 0”可能是硬约束，而“最小柴油消耗”是排序目标。

### 6.3 策略分层

后续可讨论的策略包括：

- Renewable-first greedy；
- Grid backup；
- Diesel backup；
- Load Following；
- Cycle Charging；
- Combined Dispatch；
- Predictive Dispatch；
- MILP / optimization。

建议先从少量工程可解释策略开始，不要一开始就把离网模型做成复杂 HOMER / MILP 全功能版本。应先明确策略名称、适用场景、输入、台账字段和年度指标，再考虑实现。

### 6.4 台账字段扩展问题

未来如进入柴发、离网或多来源储能，`HourlyEnergyLedger` 可能需要扩展字段，包括：

| 字段方向 | 可能字段 |
|---|---|
| 柴发 | 柴发出力、油耗、成本、排放、运行状态、启停次数 |
| 可靠性 | 缺供电量、缺供小时数、最大缺供功率、operating reserve shortfall |
| 储能来源 | 储能充电来源、绿电储能放电、非绿电储能放电 |
| 电网受限 | 下网受限缺口、上网受限弃电、电网可用状态 |
| 策略追踪 | dispatch_strategy、hour_case、constraint_flags |

最关键的是储能来源分账：一旦允许电网或柴油给储能充电，储能放电不能再天然视为绿电。需要讨论采用 FIFO、比例混合、保守法或其他分账规则。
