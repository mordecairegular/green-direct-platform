# 专家审查说明书：绿电直连 / 微电网项目方案策划软件

日期：2026-05-19  
状态：供专家审查的产品与架构重定向材料  
适用对象：能源系统仿真、微电网规划、储能调度、项目经济评价、工程软件架构专家

## 1. 为什么需要这份审查

本软件最初按“风光储多方案批量测算工具 V0.1”开发，核心能力是读取 8760 / 8784 小时负荷、光伏、风电曲线，枚举风电、光伏、储能容量组合，逐小时计算能量平衡和储能 SOC，并输出政策合规指标。

经过产品打磨后，用户认为“枚举并展示大量方案结果”并不是最终想要的使用体验。更接近目标的软件形态应是：

```text
输入项目边界和曲线
-> 系统自动审查输入是否可用
-> 内部生成并计算候选方案池
-> 按政策约束和经济性筛选
-> 推荐几个代表性方案
-> 围绕代表方案生成图表、报告和导出材料
```

因此，本次专家审查不以 UI 美观为重点，而重点审查：

- 软件要解决的问题是否定义清楚；
- 逐小时能量平衡和调度逻辑是否合理；
- 柴油发电加入后的系统逻辑是否可扩展；
- 经济性排序是否应该提前进入方案推荐；
- 模块边界、数据结构、接口方向是否适合长期演进；
- 现有 V0.1 代码资产应如何保留和迁移。

## 2. 软件要解决的问题

软件面向绿电直连、源网荷储、微电网、园区绿电供应等项目前期策划场景。用户通常需要回答：

1. 在给定负荷曲线、风光资源曲线、电网边界和政策约束下，配置多少光伏、风电、储能比较合理？
2. 哪些方案满足自发自用、绿电占比、上网比例等政策指标？
3. 在满足政策要求的基础上，哪些方案具有较好的经济性？
4. 如果考虑柴油发电，离网或弱网场景下如何保证供电可靠性？
5. 方案为什么被推荐？代价是什么？是否可以人工复核？
6. 最终能否形成适合汇报、审查、可研或内部决策的结果包？

软件不是简单的“风光储容量计算器”，也不是完整电力系统优化平台。当前目标更准确地说是：

```text
面向项目前期的多能源供电方案技术仿真、合规筛选、经济性排序和代表方案推荐工具。
```

## 4. 当前 V0.1 的核心计算口径

### 4.1 输入口径

- `load_power`：用户负荷真实功率，单位万千瓦；
- `pv_pu`：光伏标幺曲线；
- `wind_pu`：风电标幺曲线；
- 光伏、风电标幺值允许为负；
- 光伏、风电负值解释为站用电，不自动截断；
- 三条曲线必须行数一致、时间戳一致。

### 4.2 风光出力与站用电

每小时先计算原始出力：

```text
pv_power = pv_pu * pv_capacity
wind_power = wind_pu * wind_capacity
```

拆分为正发电和站用电：

```text
pv_generation_power = max(pv_power, 0)
wind_generation_power = max(wind_power, 0)

pv_station_use_power = max(-pv_power, 0)
wind_station_use_power = max(-wind_power, 0)
```

正发电先抵扣站用电，抵扣后的净新能源再参与负荷平衡：

```text
renewable_generation_power = pv_generation_power + wind_generation_power
station_use_power = pv_station_use_power + wind_station_use_power
net_renewable_power = renewable_generation_power - station_use_power
renewable_power = max(net_renewable_power, 0)
station_use_deficit_power = max(-net_renewable_power, 0)
dispatch_load_power = load_power + station_use_deficit_power
```

### 4.3 当前储能调度

当前采用逐小时贪心策略：

1. 新能源优先供负荷；
2. 新能源富余时优先给储能充电；
3. 储能充不下的富余电量按规则上网或弃电；
4. 新能源不足时储能优先放电供负荷；
5. 储能不足后由电网下网；
6. 若电网交换功率受限，则记录下网缺口。

基线规则：

- 储能只能从富余新能源充电；
- 储能不能从电网充电；
- 储能不能同小时充电和放电；
- 储能不能放电上网；
- 储能 SOC 逐小时滚动；
- SOC 受上下限约束；
- 充放电受功率、容量、效率约束。

### 4.4 政策指标

当前默认政策指标：

```text
self_use_rate = self_use_energy / total_renewable_generation
green_load_rate = self_use_energy / total_load_energy
export_rate = grid_export_energy / total_renewable_generation
```

默认达标条件：

```text
self_use_rate >= 60%
green_load_rate >= 30%
export_rate <= 20%
```

其中：

```text
self_use_energy = direct_self_use_energy + bess_discharge_to_load
```

## 5. 产品方向调整

原 V0.1 的主输出是：

```text
所有枚举方案的汇总表 + 可选逐小时明细
```

新的产品方向应是：

```text
内部仍可枚举大量方案，但主输出是经过筛选、排序、解释后的代表方案组合。
```

也就是说，枚举是计算过程，不是用户体验终点。

推荐的主输出对象：

```text
RecommendationPortfolio
```

其中包含若干代表方案，例如：

- 推荐综合方案；
- 政策达标且成本较低方案；
- 高绿电占比方案；
- 高自发自用 / 低上网方案；
- 低弃电方案；
- 低储能容量方案；
- 离网可靠性方案；
- 用户指定对照方案。

每个被推荐方案都应带：

- 方案标签；
- 容量配置；
- 政策达标情况；
- 技术指标；
- 经济性指标；
- 推荐原因；
- 主要 trade-off；
- 对应逐小时明细和图表入口。

## 6. 经济性是否应提前进入

当前判断：经济性排序应提前进入，但应分层实现。

第一阶段不必做完整财务模型，而应先做“轻量经济性排序”：

- 光伏投资；
- 风电投资；
- 储能功率投资；
- 储能容量投资；
- 柴发投资；
- 线路 / 接入 / 工程成本；
- 固定运维；
- 变量运维；
- 下网购电成本；
- 柴油燃料成本；
- 上网收入；
- 年净成本；
- LCOE-like 筛选指标；
- 简单回收期，若输入足够。

完整经济评价可后续扩展：

- NPV；
- IRR；
- 项目现金流；
- 税费；
- 折旧；
- 融资；
- 残值；
- 多年价格情景。

关键架构约束：

```text
技术仿真结果 -> 经济性评价 -> 方案排序
```

经济性评价不应反向改变当前技术仿真的逐小时调度结果。若未来要经济最优调度，应作为独立优化引擎或明确调度策略实现。

## 7. 柴发加入后的问题

用户已确认：柴发需要进入后续方案测算逻辑。

柴发加入后，软件不再只是风光储并网消纳工具，而是多能源供电系统仿真工具。它应适配：

- 并网无柴发；
- 并网加柴发备用；
- 离网风光储柴；
- 弱网 / 限网场景；
- 柴发作为可靠性兜底；
- 柴发参与经济性和碳排计算。

柴油发电不应混入 `grid_import_power`，而应有独立字段：

```text
diesel_power
diesel_generation_energy
diesel_fuel_consumption
diesel_cost
diesel_emission
```

柴发调度策略需要专门研究，不能草率写死。

需要专家重点审查的问题：

1. 离网场景下，推荐的风光储柴调度顺序是什么？
2. 并网加柴发时，柴发应作为最后兜底，还是可替代高价下网？
3. 柴发是否允许给储能充电？
4. 如果允许，储能放电的能源来源如何追踪，避免将柴油电量误算为绿电？
5. 柴发最小稳定出力、启停、爬坡、油耗曲线是否需要在初期建模？
6. 离网可靠性指标应采用缺供电量、缺供小时、最大缺供功率，还是其他指标？

## 8. 专家审查重点问题清单

### 8.1 产品问题

- 软件定位是否准确？
- 是否应该从“枚举测算工具”转为“方案推荐平台”？
- 代表方案类型是否覆盖真实项目前期需求？
- 用户看到的结果是否应隐藏大部分中间枚举结果？

### 8.2 技术仿真问题

- 当前风光负值按站用电处理是否合理？
- 储能只从富余新能源充电的口径是否适合绿电直连项目？
- 年度上网比例硬约束采用运行中累计额度的方式是否合理？
- 与电网交换功率限制同时约束上网和下网是否符合工程场景？
- 当前逐小时贪心策略是否足以做前期方案筛选？

### 8.3 柴发问题

- 柴发模型初期应简化到什么程度？
- 柴发并网和离网两种场景是否应共用同一个资产模型？
- 柴发调度是否应作为可配置策略？
- 柴发能否给储能充电？若能，如何保证绿电口径不被污染？
- 柴发与电网同时存在时，供电优先级如何设定？

### 8.4 经济性问题

- 轻量经济性排序是否足以支持推荐方案？
- 哪些成本和收益项必须第一阶段纳入？
- LCOE-like 指标是否适合用于早期排序？
- 政策达标与经济性排序应如何组合？
- 是否需要支持“同一投资主体”和“不同投资主体”两种收益分配模式？

### 8.5 架构问题

- 是否应建立统一 `HourlyEnergyLedger` 作为所有下游模块的事实表？
- `StudyResult` 是否应取代当前简单 `BatchResult` 作为上层接口？
- 大批量模式是否应只保存 summary，并按需生成选中方案明细？
- 推荐引擎、经济性、柴油调度、报告生成的模块边界是否合理？

## 9. 希望专家输出的建议

希望专家能从以下角度给出建议：

1. 当前计算口径是否存在明显技术风险；
2. 柴发加入后的最小可用模型应如何定义；
3. 经济性排序第一阶段应纳入哪些指标；
4. 推荐方案应如何分类和排序；
5. 架构拆分是否合理，是否存在过度设计或缺失模块；
6. 哪些测试用例必须补充；
7. 哪些功能应暂缓，避免早期复杂化。
