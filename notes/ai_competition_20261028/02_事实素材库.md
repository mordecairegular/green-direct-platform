## 5. 核心计算口径摘要（可直接改写进"技术实现"）

来源：`ALGORITHM_SPEC.md`、`docs/SOFTWARE_OVERVIEW_AND_INTERFACE.md` 第 11 节、`notes/architecture_reframe_20260519/01_EXPERT_REVIEW_BRIEF.md`。

- 时间尺度：全年逐小时，支持 8760 / 8784 小时；
- 风光负值：标幺曲线负值解释为站用电，先由同小时正发电抵扣，不足部分并入下网需求；
- 调度顺序：新能源优先供荷 → 富余充储能 → 充不下的按规则上网或弃电；新能源不足 → 储能放电 → 电网下网；
- 储能约束：只从富余新能源充电；不从电网充电；不同小时充放；不放电上网；SOC 逐时滚动且受上下限、功率、容量、效率约束；
- 上网约束：年度上网比例按运行中累计额度硬约束，额度用尽后富余转弃电；可选与电网交换功率限制（同时约束上网和下网）；
- 政策指标：自发自用率 = 自发自用电量 / 新能源总可用发电量；绿电占比 = 自发自用电量 / 用户总用电量；上网比例 = 上网电量 / 新能源总可用发电量；默认门槛 60% / 30% / 20%（可调）；
- 经济性：Year 0 建设、默认运营 25 年、不考虑贷款；输出年度现金流、FNPV、FIRR、静态 / 动态回收期；储能更换按循环寿命与日历寿命先到者；
- 推荐：先过滤政策达标方案，再按各席位指标排序；负荷侧席位必须先满足用户设定的电源侧最低 FIRR；同一方案命中多个席位时合并标签；
- 架构原则：技术仿真是唯一事实来源，经济性、推荐、图表、报告只读不改；`scenario_id` 贯穿全部模块。

## 9B. 性能实测（2026-10-30）

- 命令：`python scripts/benchmark_internal_pilot_performance.py --hours 8760 --pv-count 8 --wind-count 8 --bess-power-count 3 --durations 0,2,4 --skip-full-retention --no-tracemalloc`
- 结果：315 个方案、8760 小时、单进程，技术仿真（汇总优先，保留 20 个方案明细）2.60 秒；经济性汇总测算 0.10 秒。
- 环境：云端 Linux 容器（4 核），代码版本为 2026-07-05 提交 `2deda91`；用户 Windows 机器和最新版结果可能不同。
