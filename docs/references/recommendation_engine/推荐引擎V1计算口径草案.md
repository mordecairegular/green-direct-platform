# 推荐引擎 V1 计算口径草案

> 状态：V1 试用口径，2026-05-28 更新。本文用于沉淀推荐席位、输入参数和价格曲线口径；已落地固定价版本，价格曲线和更完整数据模型后续扩展。

## 1. 定位

推荐引擎不是新的调度引擎。V1 应读取技术仿真得到的 `summary`、必要时读取选中方案的 `hourly_detail`，再叠加经济性评价结果和价格输入，生成少量可解释的 `RecommendationPortfolio`。

推荐层不得反向修改风光储调度、SOC、上网、弃电、自发自用等技术结果。若未来要按电价优化储能充放电，应作为新的显式 `DispatchStrategy` 或优化引擎单独实现。

默认推荐组合先保留四个席位：

1. 同一主体 FIRR 最优；
2. 电源侧 FIRR 最优；
3. 负荷侧可成交收益最优；
4. 工程代表方案，默认政策达标最小投资，可切换为低弃电、高绿电占比、高自发自用。

如果同一方案命中多个席位，推荐结果合并标签，不硬凑多个卡片。如果经济性评价未运行，前三个经济席位显示“待经济性评价”，第四个工程代表方案仍可给出。

所有默认推荐席位都在政策达标候选集内排序。也就是说，先过滤 `pass_policy == True` 的方案，再按各席位自己的经济或工程指标排序。政策不达标方案不参与默认推荐，只进入诊断、失败原因说明或后续敏感性分析。

## 2. 共用技术字段

推荐引擎 V1 至少依赖以下技术字段：

| 字段                           | 含义             | 用途            |
| ---------------------------- | -------------- | ------------- |
| `scenario_id`                | 方案唯一编号         | 跨模块关联         |
| `pv_capacity`                | 光伏容量，万千瓦       | 展示与投资估算       |
| `wind_capacity`              | 风电容量，万千瓦       | 展示与投资估算       |
| `bess_power`                 | 储能功率，万千瓦       | 展示与投资估算       |
| `bess_energy`                | 储能容量，万千瓦时      | 展示与投资估算       |
| `total_load_energy`          | 年用电量，万千瓦时      | 绿电占比、负荷侧展示    |
| `total_renewable_generation` | 年可用新能源发电量，万千瓦时 | 自发自用率、弃电率、上网率 |
| `self_use_energy`            | 新能源自发自用电量，万千瓦时 | 三个经济席位的核心电量   |
| `grid_export_energy`         | 上网电量，万千瓦时      | 同一主体与电源侧收益    |
| `curtail_energy`             | 弃电量，万千瓦时       | 工程代表方案        |
| `self_use_rate`              | 自发自用率          | 高自发自用方案       |
| `green_load_rate`            | 绿电占比           | 高绿电占比方案       |
| `export_rate`                | 上网比例           | 政策筛选与展示       |
| `curtail_rate`               | 弃电率            | 低弃电方案         |
| `pass_policy`                | 是否满足政策约束       | 推荐前置过滤        |
| `fail_reasons`               | 不满足政策原因        | 解释说明          |

如果采用逐时价格曲线，推荐层还需要读取 `hourly_detail` 中的：

| 字段                      | 用途                    |
| ----------------------- | --------------------- |
| `timestamp`             | 对齐价格曲线                |
| `hour_index`            | 在缺少时间戳或做数组对齐时使用       |
| `direct_self_use_power` | 逐时直接自发自用电量计算          |
| `bess_discharge_power`  | 当前基线下储能放电到负荷计入新能源自发自用 |
| `grid_export_power`     | 逐时上网电量计算              |
| `curtail_power`         | 工程代表方案解释              |

逐时自发自用电量：

```text
self_use_energy_t =
  (direct_self_use_power_t + bess_discharge_power_t) * dt_hours
```

当前基线储能只能由富余新能源充电，因此 `bess_discharge_power` 可计入绿电自发自用。未来若引入柴油或电网给储能充电，必须先引入来源标签，不能默认把所有储能放电计入绿电自发自用。

## 3. 共用经济与价格输入

### 3.1 当前已存在的经济性输入

当前经济性 V1 已有：

| 字段 | 当前含义 | 需要注意 |
|---|---|---|
| `grid_export_price_with_vat` | 上网电价，元/kWh，含税 | 电源侧收入 |
| `green_power_settlement_price_with_vat` | 绿电结算价，元/kWh，含税 | 后续全局统一字段；当前代码中的 `self_use_price_with_vat` 仅作为待迁移旧字段 |
| `dedicated_connection_line_investment_with_vat` | 送出线路工程投资，万元，含税 | Year 0 必需投资 |
| `other_fixed_asset_investment_with_vat` | 其他固定资产投资，万元，含税 | 不再吞并送出线路 |
| `wind/pv/bess_capex_*` | 风光储单位造价 | 初始投资估算 |
| `wind/pv/bess_om_*` | 风光储运维成本 | 年度成本 |
| `bess_replacement_*` | 储能更换参数 | 运营期新增投资和折旧 |
| `discount_rate` | 折现率 | 用于 FNPV 和动态回收期，不用于 FIRR |

### 3.2 推荐 V1 需要补充的价格输入

固定价模式下建议补充或重命名为：

| 推荐字段                                    | 单位       | 默认处理                              | 用途                 |
| --------------------------------------- | -------- | --------------------------------- | ------------------ |
| `green_power_settlement_price_with_vat` | 元/kWh，含税 | 全局统一字段 | 电源侧卖绿电收入、负荷侧购买绿电成本 |
| `net_avoided_grid_cost_price`           | 元/kWh    | 同一主体默认简化输入                        | 同一主体外部购电净成本单价 |
| `load_side_avoided_charge_price`        | 元/kWh    | 负荷侧固定价输入或组价推导                    | 负荷侧与绿电结算价比较的可减少购网费用单价 |
| `grid_purchase_price_with_vat`          | 元/kWh，含税 | 后续价格曲线或更细账单模型输入                 | 负荷侧原购网电价的上层来源之一 |
| `grid_export_price_with_vat`            | 元/kWh，含税 | 沿用现有字段                            | 上网售电收入             |
| `environmental_value_per_kwh`          | 元/kWh    | 高级选项，默认 0                         | 同一主体或负荷侧可选环境价值收益   |

说明：

- 上述固定价参数是推荐席位的共同基础输入，应默认显示在经济性参数区，不应隐藏在“启用同一主体”或“启用负荷侧”之类的视角开关后面。经济性测算入口应一次计算当前已实现的所有视角。
- 经济性参数区建议按“基本参数”“成本费用”“收入和税金”等分组。资金来源/贷款暂不纳入 V1。
- “基本参数”应包含 Year 0 建设投资相关参数：风电、光伏、储能单位造价，送出线路工程投资，其他固定资产投资，以及建设投资进项税率。“成本费用”主要面向运营期，包含风光储运维、其他运行成本和储能更换；储能更换应说明发生年份以日历寿命和循环寿命哪个先到为准。
- 建议新增“电费构成参数”分区，承载电能量/市场购电价格、线损费用、输配电价、系统运行费、政府基金及附加等账单项目。该分区既服务同一主体外部购电净成本组价，也为后续负荷侧节费价差口径预留。
- “自发自用电价”容易混淆。正式命名统一为“绿电结算价”，计算字段统一为 `green_power_settlement_price_with_vat`。站在电源侧，它是收入；站在负荷侧，它是购买绿电成本；站在同一主体口径下，它不应再被当成内部收益重复计算。UI 可解释为“自发自用绿电的结算电价”。它不是用户到户电价，不含输配电价、政府基金及附加、系统运行费和容需量电费等。
- 两部制电价 V1 暂不计算，默认容量电费不因绿电直连方案变化。后续可作为高级参数研究。
- 环境价值收益先采用用户自定义的每 kWh 固定价值，不强行命名为绿证、碳税或碳减排收益，暂不设计时间价值曲线。精确定义可在项目适用政策明确后再扩展。
- 同一主体 FIRR 不直接使用 `green_power_settlement_price_with_vat` 计算收益；默认直接输入 `net_avoided_grid_cost_price`。如启用组价模式，应使用能对应电费清单的字段：电能量/市场购电价格、上网环节线损费用、系统运行费用、输配电价、政府性基金及附加。详细口径见 `同一主体购电节费与税前FIRR口径.md`。
- `net_avoided_grid_cost_price` 是同一主体口径下每 1 kWh 自发自用绿电替代外部购电带来的税前净节费。它应等于原外部购网电电量类成本，扣除绿电直连自发自用仍需缴纳的费用；容需量电费、力调电费等非电量费用本阶段默认不参与。它不等同于负荷侧比较绿电结算价时使用的到户电量电费口径。
- 负荷侧可成交收益使用 `load_side_avoided_charge_price`，表示负荷侧每 1 kWh 自发自用绿电可减少的购网费用现金口径。为减少默认输入，固定价模式可先复用同一价格作为筛选近似；精确区分时应启用电费清单组价，或在高级选项中单独覆盖负荷侧单价。

同一主体组价公式：

```text
外部购电净成本单价 =
  原外部购网电电量类成本单价
  - 绿电直连自发自用仍需缴纳费用单价
```

展开为：

```text
原外部购网电电量类成本单价 =
  (电能量/市场购电价格 + 线损费用 + 系统运行费用 + 输配电价)
  ÷ (1 + 电网购电增值税率)
  + 政府性基金及附加

绿电直连自发自用仍需缴纳费用单价 =
  绿电仍缴输配电价 ÷ (1 + 电网购电增值税率)
  + 绿电仍缴政府性基金及附加
```

政府性基金及附加暂按无增值税电量附加处理，不参与价税分离。1192 号文系统运行费暂按下网电量缴纳，自发自用绿电不作为“绿电仍缴系统运行费用”扣减；若当前项目口径认为自发自用绿电仍缴输配电价和政府性基金及附加，则这两项不能算作节省。

负荷侧节费价差简化口径示例：

```text
节约电费单价 =
  (电量电价 + 线损 + 输配 + 系统运行 + 政府基金及附加)
  - (绿电结算价 + 输配 + 政府基金及附加)
```

若输配和政府基金两边口径一致，可在差额中抵消。逐时价格版本则按每个时间步分别计算价差，再乘以逐时自发自用电量。

### 3.3 逐时价格曲线输入

价格曲线应作为经济性与推荐层读取的时序输入，采用 CSV/Excel 模板上传，不做网页逐项录入。

建议第一版价格曲线模板字段：

| 字段                                      | 单位       | 是否必需 | 用途                             |
| --------------------------------------- | -------- | ---- | ------------------------------ |
| `timestamp`                             | 时间       | 必需   | 与 `hourly_detail.timestamp` 对齐 |
| `green_power_settlement_price_with_vat` | 元/kWh，含税 | 可选   | 绿电结算价曲线                        |
| `grid_purchase_price_with_vat`          | 元/kWh，含税 | 可选   | 电网购电价曲线                         |
| `net_avoided_grid_cost_price`           | 元/kWh    | 可选   | 同一主体外部购电净成本单价曲线             |
| `grid_export_price_with_vat`            | 元/kWh，含税 | 可选   | 上网电价曲线                         |

规则建议：

- 若某项曲线缺失，则使用对应固定价。
- 若曲线存在，应与技术仿真时间步一一对齐，V1 支持 8760 / 8784 小时。
- 15min 曲线后续支持；启用前需要确认技术仿真输入、`dt_hours`、输出明细和价格模板均支持 15min。
- 电价曲线只影响经济性和推荐排序，不影响当前基线调度。

## 4. 推荐席位计算口径

### 4.1 同一主体 FIRR 最优

适用场景：电源和负荷处在同一投资主体或同一经济决策边界内。绿电直连工程作为相对基准用能方案的增量投资进行评价。

排序目标：以新增全部投资对应的税前全投资内部收益率 FIRR 最高为主排序。

同一主体合并口径下，内部绿电结算价不是新增收益来源。该席位不使用 `green_power_settlement_price_with_vat` 计算自发自用收益，而使用自发自用绿电替代外部购电形成的净节费。

投资口径：

```text
Year 0 初始投资 =
  风电投资 + 光伏投资 + 储能投资
  + 送出线路工程投资 + 其他固定资产投资
```

固定价收益口径建议：

```text
被替代外部购电净成本单价 =
  net_avoided_grid_cost_price
```

```text
年度增量收益 =
  self_use_energy * net_avoided_grid_cost_price
  + grid_export_energy * grid_export_price_with_vat / (1 + output_vat_rate)
  + self_use_energy * environmental_value_per_kwh
```

中文等价公式：

```text
被替代外部购电净成本单价 =
  用户直接输入的外部购电净成本单价
  或按电费清单组价后的净成本单价
```

```text
年度增量收益 =
  自发自用电量 * 被替代外部购电净成本单价
  + 上网电量 * 上网含税电价 ÷（1 + 上网电力销售增值税率）
  + 自发自用电量 * 环境价值单价
```

年度增量成本包括风光储运维、其他经营成本、储能更换现金流和其他项目现金成本。V1 主排序采用税前 FIRR，不默认扣减所得税。弃电和储能充放损耗对应电量不计入收益。

逐时价格收益口径：

```text
年度增量收益 =
  Σ(self_use_energy_t * net_avoided_grid_cost_price_t)
  + Σ(grid_export_energy_t * grid_export_price_t / (1 + output_vat_rate))
  + self_use_energy * environmental_value_per_kwh
```

中文等价公式：

```text
年度增量收益 =
  Σ(逐时自发自用电量 * 逐时被替代外部购电净成本单价)
  + Σ(逐时上网电量 * 逐时上网含税电价 ÷（1 + 上网电力销售增值税率）)
  + 自发自用电量 * 环境价值单价
```

环境价值暂按固定单价处理，不设置逐时环境价值曲线。

默认排序链：

1. FIRR 可可靠计算；
2. FIRR 从高到低；
3. 静态回收期更短；
4. 动态回收期更短；
5. FNPV 更高。

同一主体推荐席位的详细输入、公式、校验和报告说明见 `同一主体购电节费与税前FIRR口径.md`。如果后续要启用税后测算，应作为高级模型，不影响 V1 主排序。

试用中也允许把同一主体席位切换为“动态回收期最短”。该视角更偏快速收回投资，通常会偏向投资较小、现金流回正更快的方案；它不替代 FIRR 主视角，而是用于回答“更快回本”的工程决策问题。

### 4.2 电源侧 FIRR 最优

适用场景：电源侧投资方与负荷侧用户为不同主体。电源侧投资方关注风、光、储、送出线路及其他资产的投资收益。

排序目标：使用当前经济性 V1 口径，以电源侧 FIRR 最高为主排序。

固定价收入口径：

```text
年度售电收入 =
  self_use_energy * green_power_settlement_price_with_vat
  + grid_export_energy * grid_export_price_with_vat
```

中文等价公式：

```text
年度售电收入 =
  自发自用电量 * 绿电结算价
  + 上网电量 * 上网电价
```

逐时价格收入口径：

```text
年度售电收入 =
  Σ(self_use_energy_t * green_power_settlement_price_t)
  + Σ(grid_export_energy_t * grid_export_price_t)
```

中文等价公式：

```text
年度售电收入 =
  Σ(逐时自发自用电量 * 逐时绿电结算价)
  + Σ(逐时上网电量 * 逐时上网电价)
```

排序链已确认：

1. FIRR 可可靠计算；
2. FIRR 从高到低；
3. 静态回收期更短；
4. 动态回收期更短；
5. FNPV 更高。

### 4.3 负荷侧可成交收益最优

适用场景：负荷侧用户不承担初始投资，但推荐结果仍需具备交易成立可能。该席位不是单纯寻找“负荷侧收益绝对值最大”的方案，而是在电源侧投资收益满足最低可接受水平的候选集内，寻找负荷侧综合用能收益最优方案。

该席位不应称为“负荷侧 FIRR 最优”。由于负荷侧没有初始投资现金流，IRR 没有经济含义。推荐名称建议为“负荷侧可成交收益最优”，高级模式中可另保留“纯负荷侧收益最大”作为谈判边界参考。

新增基础参数：

| 字段 | 中文名 | 单位 | 默认值 | 说明 |
|---|---|---:|---:|---|
| `min_power_side_acceptable_firr` | 电源侧最低可接受 FIRR | decimal | 0.07 | 负荷侧可成交收益席位的筛选门槛，放在基本参数区。若用户清空该参数，则不对本席位默认排序，并在推荐结果处提示缺少可成交性约束。 |

V1 不反算绿电结算价。推荐引擎只在用户给定绿电结算价、上网电价和费用参数的条件下排序；反算绿电结算价属于价格谈判或均衡求解模型，后续版本再研究。

候选集筛选：

1. 政策达标；
2. 负荷侧年度综合用能收益大于 0；
3. 已运行电源侧经济性，且电源侧 FIRR 可可靠计算；
4. 电源侧 FIRR 大于等于 `min_power_side_acceptable_firr`。

若经济性未运行，或用户清空 `min_power_side_acceptable_firr`，本席位不默认给出排序结果，应显示“待电源侧经评/缺少最低可接受 FIRR”的提示。

固定价收益口径：

```text
负荷侧年度综合用能收益 =
  self_use_energy * load_side_saving_price
  + self_use_energy * environmental_value_per_kwh
```

```text
load_side_saving_price =
  original_grid_reducible_energy_charge
  - green_direct_retained_charge
  - green_power_settlement_price_with_vat
```

中文等价公式：

```text
负荷侧年度综合用能收益 =
  自发自用电量 * 负荷侧节约电费单价
  + 自发自用电量 * 环境价值单价
```

```text
负荷侧节约电费单价 =
  原外部购网电可减少费用单价
  - 绿电直连后仍需支付费用单价
  - 绿电结算价
```

逐时价格收益口径：

```text
负荷侧年度综合用能收益 =
  Σ[
    self_use_energy_t
    * load_side_saving_price_t
  ]
  + self_use_energy * environmental_value_per_kwh
```

中文等价公式：

```text
负荷侧年度综合用能收益 =
  Σ[逐时自发自用电量 * 逐时负荷侧节约电费单价]
  + 自发自用电量 * 环境价值单价
```

排序链建议：

1. 负荷侧年度综合用能收益从高到低；
2. 电源侧 FIRR 更高；
3. 电源侧静态回收期更短；
4. 初始投资更低；
5. 绿电占比 `green_load_rate` 更高；
6. 弃电率更低。

注意：

- 不直接用 `grid_import_energy` 计算节费，因为当前 `grid_import_energy` 可能包含站用电缺口等技术口径；负荷侧节费核心是自发自用绿电替代了多少电网购电。
- 如果绿电结算价高于负荷侧可减少费用且环境价值为 0，该指标可能为负。默认可成交席位应排除负荷侧收益为负的方案；高级“纯负荷侧收益最大”可展示边界方案，但必须提示“负荷侧成本增加风险”或“电源侧 FIRR 未达最低可接受水平”。
- 环境价值作为高级选项默认 0。启用后仅按自发自用电量线性增加收益，暂不展开绿证、碳税、碳减排收益等专业名词。实际项目中负荷侧通常不一定能享受该收益，因此应由用户显式启用。

### 4.4 工程代表方案

工程代表方案不一定依赖经济性评价。V1 默认使用“政策达标最小投资”，用户可切换为其他工程视角。这样更像一个可落地的工程基准方案；低弃电方案仍保留，用于关注弃电控制或消纳压力的场景。

可选视角：

| 视角 | 主排序 | 辅助排序建议 |
|---|---|---|
| 政策达标最小投资 | `construction_cash_outflow` 从低到高 | 绿电占比更高、弃电率更低 |
| 低弃电 | `curtail_rate` 从低到高 | `curtail_energy` 更低、初始投资更低 |
| 高绿电占比 | `green_load_rate` 从高到低 | `self_use_energy` 更高、初始投资更低 |
| 高自发自用 | `self_use_rate` 从高到低 | `curtail_rate` 更低、初始投资更低 |

其中政策达标最小投资若已运行经济性评价，优先使用经济性 V1 输出的 `construction_cash_outflow`；若未运行经济性评价，可先用风光储容量和用户输入的单位造价、送出线路投资、其他固定资产投资估算。

## 5. 第一版实现边界建议

当前实现和下一步建议：

1. 已实现四个默认推荐席位：`同一主体 FIRR 最优`、`电源侧 FIRR 最优`、`负荷侧可成交收益最优` 和 `工程代表方案`。完成经济性评价后应同时构造四个席位；同一 `scenario_id` 命中多个席位时合并标签，不硬凑重复卡片；合并时必须同时保留各席位带来的关键指标，不能只合并标签；
2. 同一主体税前 FIRR 已按独立节费模型实现，不能复用电源侧 `evaluate_scenario_economy()`；
3. 电源侧 FIRR 继续沿用当前经济性 V1 口径，后续重点是字段迁移和逐时价格曲线；
4. 负荷侧可成交收益当前为固定价版本。逐时价格曲线后续再接入 CSV/Excel 模板，因为本质是基于逐时自发自用电量的加权求和，不需要完整年度现金流和 FIRR；
5. 价格曲线使用 CSV/Excel 模板上传，V1 不做网页逐项录入；
6. 所有推荐结果必须保留 `scenario_id`、席位标签、排序依据、关键技术指标、关键经济指标、推荐理由和风险提示。若某个席位暂不能排序，应显示 `pending` 或 `no_candidate` 原因，不应静默消失。

## 6. 实现注意事项

1. 当前代码中的 `self_use_price_with_vat` 仍是迁移期旧字段，推荐引擎长期字段应统一为 `green_power_settlement_price_with_vat`。
2. 同一主体税前 FIRR 不使用绿电结算价计算整体收益，也不默认模拟自发自用内部销项税。
3. 同一主体税前 FIRR 使用被替代外部购电净成本单价；详细公式、校验和报告说明见 `同一主体购电节费与税前FIRR口径.md`。
4. 负荷侧可成交收益席位依赖电源侧经济性结果和 `min_power_side_acceptable_firr`；不能只按负荷侧收益绝对值最大推荐。
5. 当前输入链路主要支持 8760 / 8784 小时；15min 需要后续同步扩展输入校验、UI、导出和图表。
