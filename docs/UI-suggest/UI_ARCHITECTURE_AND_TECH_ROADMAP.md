# UI 架构与改进计划

> 创建日期：2026-05-23
> 背景：讨论确认了 UI 模块架构、页面流程、以及从 Streamlit 原型到正式版的技术路线。

## Context

本项目已有完整的技术计算引擎（V0.1 风光储贪心调度、批量遍历、政策筛选），但 UI 层（Streamlit 原型）体验不佳。用户编程基础弱、主要靠自然语言驱动开发，最大痛点是 AI 生成的 UI 代码"哪哪都不对"。

长期目标：本地 demo → 公网部署（域名/服务器） → 可能上微信小程序。

## 一、确认的页面流程（5 步向导式）

```
┌──────────────────────────────────────────────────┐
│  Step 1: 参数输入                                 │
│  (数据上传 + 容量搜索范围 + 储能参数 +             │

└──────────────────────────────────────────────────┘

│  ┌─ 顶部摘要条 ─────────────────────── [修改参数]│
│  │ 光伏 5-20MW / 风电 0-10MW / 储能 2-8MWh       │
│  └────────────────────────────────────────────── │
│  Step 2: 遍历概览 — 政策合规全景                   │
│  "共 1200 个方案, 340 个满足政策, 860 不合规"      │

│  ① 同一主体 FIRR 最优                            │

│  - 方案总览：关键指标汇总                          │
│  - 能量流向：Sankey 图或流向表                     │
│  - 时序详图：典型日/典型季/8760 曲线               │
```

### 关键设计决策

- **参数输入**：向导式，填完后提交进入后续步骤，不在后续页面展示完整参数面板
- **顶部摘要条**：后续页面顶部始终显示关键参数摘要（如"光伏 5-20MW / 风电 0-10MW / 储能 2-8MWh"），点击可跳回修改
- **遍历概览与推荐概览分开**：遍历概览展示全量方案的政策合规分布（有助于了解"多少方案合规"），推荐概览展示经济性排序后的代表方案

## 二、AI 辅助 UI 设计工具对比

| 工具 | 做什么 | 优势 | 局限 |
|------|--------|------|------|
| **v0.dev** (Vercel) | 用自然语言生成 React/Next.js UI 组件 | 生成质量最高，可直接出 production-ready 代码 | 生成的是 React 代码，需要前后端分离架构 |
| **Bolt.new / Lovable** | 用自然语言生成完整网页应用 | 全栈生成，一句话出完整应用 | 同上，生成的是 JS/TS 前端 |
| **Figma + AI 插件** | 先做视觉设计稿，再导出代码 | 设计和开发分离，先确定"长什么样" | 导出代码仍需前端框架 |
| **Claude Code / Cursor** | 在现有项目里用自然语言修改代码 | 对 Streamlit 修改最直接 | 受限于 Streamlit 框架的 UI 表达力 |
| **Streamlit** | 当前使用的 Python UI 框架 | 最简单，Python 即可 | UI 上限像 Excel 报表风格，不适合复杂交互 |
| **Reflex** | 纯 Python 写 React 式 UI | 不需要学 JS，比 Streamlit 好看 | 需要重写 UI 层 |

## 三、UI 技术路线建议

### 近期（Phase 1-6，完成 demo）：继续 Streamlit

- 用 `st.tabs()` 或 `st.session_state` 实现向导式步骤切换
- 用 `st.container()` + 自定义 CSS 实现顶部摘要条
- 用 `st.columns()` + CSS 做推荐方案卡片
- 目标是"功能完整、逻辑清晰"，不追求视觉惊艳

### 正式版（Phase 7+，上线部署）：前后端分离

推荐架构：
```
Python 后端 (FastAPI)     ←→    前端 (React/Next.js)
  ├─ core/                          ├─ 用 v0.dev 生成
  ├─ batch/                         ├─ 部署到 Vercel / 阿里云
  ├─ economy/                       └─ 可改造为微信小程序 (Taro)
  ├─ recommendation/
  └─ REST API endpoints
```

- **v0.dev**：在 demo 跑通后，用自然语言在 v0.dev 上设计理想 UI
- **FastAPI**：从现有 Python 逻辑中提取 API（Claude Code 可自动完成）
- **部署**：前端 Vercel（免费）+ 后端阿里云/腾讯云轻量服务器
- **微信小程序**：用 Taro/uni-app 复用 React 组件，对接同一套 API

### 改善当前 Streamlit UI 的关键要点

给 Claude Code 下 UI 指令时，应包含：
1. **具体的布局规格**（不要只说"做个页面"）：列宽、间距、对齐方式
2. **视觉参考**：描述你见过的类似界面（如"像支付宝账单页面那样的卡片"）
3. **交互行为**：点击后发生什么、什么时候显示/隐藏
4. **数据映射**：哪个变量对应页面上哪个位置
