# 在线网页与 UI 工作流重构方案

状态：2026-06-02 Phase 1 已落地为工程工作台第一版
目的：回应当前“所有功能挤在一个页面里”的体验问题，并为后续在线化运行做架构准备。

## 1. 判断结论

不建议立刻做完整的 FastAPI / React 重写。

当前更合适的顺序是：

```text
先把产品工作流拆清楚
-> 再把 Streamlit 单页改成分步骤 / 分页面体验
-> 同时抽出服务层和 StudyResult
-> 图表围绕推荐方案重做
-> 最后再决定是否迁移到正式前后端架构
```

原因：

- 当前经济性和推荐口径仍在快速收敛，直接重写前端会扩大返工面；
- 现有 Streamlit 能快速验证业务工作流，适合先打磨信息架构；
- 真正影响在线流畅运行的不是 UI 框架本身，而是缺少 `StudyResult`、`ResultStore`、按需加载逐时明细和清晰服务边界；
- 图表模块需要重新设计，尤其是 8760 时序展示、典型日、缩放和多指标联动。这部分应先有清楚的数据接口，再决定最终图表技术栈。

## 2. 目标工作流

建议把主体验拆成六个一级页面：

```text
欢迎页
-> 方案仿真
-> 经济性测算
-> 方案推荐
-> 图表概览
-> 图表下载和报告生成
```

### 2.1 欢迎页

目标：让用户知道这是“绿电直连 / 微电网方案策划与推荐平台”，而不是一个裸批量表格工具。

内容：

- 项目名称和当前研究任务；
- 数据准备状态；
- 最近一次测算状态；
- 进入方案仿真的主按钮；
- 当前版本能力边界提示。

不建议在欢迎页放大表格、大量参数或逐时曲线。

### 2.2 方案仿真页

目标：完成输入数据、方案遍历参数和技术仿真。

页面结构：

- 项目基本信息；
- 系统架构简图：负荷、光伏、风电、储能、电网，后续扩展柴油；
- 三条曲线上传与诊断；
- 方案遍历参数：风、光、储范围和步长；
- 储能参数、政策参数、电网约束；
- 执行技术仿真；
- 展示输入诊断、方案数量、政策达标概览。

默认结果不展示全量枚举大表，只展示：

- 方案数量；
- 达标数量；
- 主要技术指标范围；
- 全量技术汇总留到“图表下载和报告生成”页导出；
- 下一步进入经济性测算。

### 2.3 经济性测算页

目标：设置经济参数，计算当前已实现的经济性视角。

页面结构：

- 基本参数：运营期、折现率、最低可接受电源侧 FIRR；
- Year 0 建设投资；
- 成本费用；
- 收入和税金；
- 电费构成参数；
- 高级价格曲线上传；
- 执行经济性测算。

默认展示：

- 电源侧经济性摘要；
- 同一主体经济性摘要；
- 关键参数口径说明；
- 年度现金流导出入口集中到“图表下载和报告生成”页。

不建议展示所有年度现金流大表，只对选定方案下载或展开。

### 2.4 方案推荐页

目标：把用户注意力从“全量枚举表”转到代表方案组合。

页面结构：

- 推荐组合卡片；
- 用户指定 / 钉选方案；
- 推荐理由、风险提示和席位命中解释；
- 推荐组合明细和负荷侧复核作为高级展开；
- 进入图表概览。

默认推荐席位：

- 同一主体视角，默认 FIRR 最优，可切换动态回收期最短；
- 电源侧 FIRR 最优；
- 负荷侧可成交收益最优；
- 工程代表方案，默认政策达标最小投资，可切换低弃电、高绿电占比、高自发自用。

如果同一个方案命中多个席位，继续合并标签，但需要在卡片中解释为什么多个席位重合。

### 2.5 图表概览页

目标：围绕推荐组合和当前代表方案展示图表，不再把推荐卡片和完整图表分析堆在同一个长页面里。

页面结构：

- 多方案关键指标对比；
- 24H 典型日运行曲线；
- 能量流向、运行时序和完整图表分析作为高级复核区；
- 进入图表下载和报告生成。

默认图表只围绕推荐组合和当前报告方案；全量枚举结果不作为主视图。

### 2.6 图表下载和报告生成页

目标：把导出动作从仿真和图表主流程中分离出来，避免主界面被下载按钮和大文件准备逻辑淹没。

页面结构：

- 选择一个方案作为报告和逐小时复核对象；
- 下载方案汇总 Excel；
- 下载全部逐小时明细 ZIP；
- 下载所选方案逐小时 CSV；
- 下载所选方案图表 HTML ZIP；
- 下载技术+经济汇总 Excel；
- 生成简版 Markdown 报告；
- 后续接入图表 PNG 批量导出。

## 3. 图表设计重点

图表模块不应继续围绕全量枚举结果打磨，而应围绕推荐方案和用户钉选方案重做。

### 3.1 方案总览

目标：快速读懂一个方案为什么被推荐。

建议图表：

- 容量配置条形图：风、光、储功率、储能容量；
- 关键技术指标：绿电占比、自发自用率、上网比例、弃电率；
- 关键经济指标：FIRR、FNPV、回收期、初始投资；
- 推荐理由和风险提示。

### 3.2 能量流向

目标：解释年电量去向。

建议图表：

- 年度能量流向 Sankey 或分层条图；
- 新能源发电量拆分：直接自用、储能后自用、上网、弃电；
- 负荷供电来源：新能源直接、储能、电网，后续扩展柴油；
- 储能充放电与损耗。

### 3.3 运行曲线

这是最需要仔细设计的模块，因为 8760 时序长、指标多、缩放复杂。

建议采用多层级视图：

```text
全年概览
-> 月/周筛选
-> 典型日对比
-> 原始 8760 曲线缩放
```

推荐组件：

- 全年热力图：按日期 x 小时展示负荷、新能源出力、下网或弃电强度；
- 典型日曲线：冬夏春秋、工作日/节假日、最高负荷日、最高弃电日、最低 SOC 日；
- 多轴时序图：负荷、光伏、风电、储能充放电、下网、上网、弃电；
- 缩放和刷选：默认展示一周或一天，避免一次性画满全部 8760 点；
- 图例开关：用户可以隐藏部分曲线；
- 指标分组：不要把功率、电量、SOC、价格、现金流全部画到一张图上。

性能原则：

- summary 常驻内存；
- 逐时明细只为推荐方案和用户钉选方案加载；
- 8760 曲线前端展示时先抽样 / 聚合，用户缩放到局部再加载高分辨率；
- 图表只读消费技术和经济结果，不改变调度。

## 4. 服务层与数据对象

为了后续在线化，下一步应抽出这些对象或服务：

```text
ProjectStudyInput
TechnicalStudyResult
EconomicStudyResult
RecommendationPortfolio
SelectedScenarioAnalysis
StudyResult
ResultStore
```

建议服务函数：

```text
run_technical_study(inputs) -> TechnicalStudyResult
run_economic_evaluation(technical_result, economy_params) -> EconomicStudyResult
build_recommendations(technical_result, economic_result, recommendation_params) -> RecommendationPortfolio
build_selected_scenario_analysis(study_result, scenario_ids) -> SelectedScenarioAnalysis
```

Streamlit 页面只负责：

- 收集输入；
- 调用服务；
- 展示结果；
- 触发导出。

## 5. 分阶段实施建议

### Phase 1：当前 Streamlit 工作流拆分

目标：不换技术栈，先解决一个页面过载。

任务：

- 引入页面导航状态；
- 把现有函数拆成欢迎、方案仿真、经济性测算、方案推荐、图表概览、下载报告六个页面；
- 保持现有计算逻辑不变；
- 保持测试通过。

### Phase 2：服务层抽取

目标：为在线化和后续 FastAPI 做准备。

任务：

- 从 `ui/app.py` 中抽出技术仿真编排；
- 抽出经济性测算编排；
- 抽出推荐组合构建；
- 初步定义 `StudyResult`。

### Phase 3：推荐方案图表重构

目标：围绕代表方案，而不是全量枚举表。

任务：

- 方案总览图；
- 能量流向图；
- 典型日曲线；
- 8760 曲线缩放策略；
- 用户钉选方案对比。

### Phase 4：在线化评估

目标：判断是否需要从 Streamlit 迁移到正式前后端。

触发条件：

- 多用户并发；
- 任务队列和长耗时计算；
- 账户、权限、项目保存；
- 大结果存储；
- 更复杂的交互式图表。

可能架构：

```text
FastAPI 后端
+ 任务队列 / ResultStore
+ React 或 Next.js 前端
+ ECharts / Plotly 图表
```

在这些条件出现前，建议先把 Streamlit 做成清晰工作流，不急于重写。
