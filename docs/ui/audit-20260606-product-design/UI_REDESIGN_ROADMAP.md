# UI Redesign Roadmap

日期：2026-06-06

原则：只改 UI 展示层、样式、文档和 UI 测试；不改技术仿真、储能调度、经济性计算、推荐排序口径和既有数据结构。

## North Star

把当前 Streamlit 应用从“参数 + 表格 + 图表堆叠页”收敛成“绿电直连 / 微电网方案策划工作台”：

```text
项目输入
-> 输入诊断
-> 候选方案池
-> 技术仿真
-> 经济性测算
-> 推荐组合决策
-> 图表复核
-> 交付导出
```

枚举仍是内部搜索方法，用户主界面只看少量代表方案、推荐理由、风险和可复核证据。

## Phase 0. Guardrails And UI Contract

目标：先给 UI 改造上护栏，避免“改好看”时碰到底层口径。

交付：

- 新增或补强 `docs/ui/UI_SPEC.md`，固化工作台视觉、组件、状态和图表规则。
- 定义 UI 只读消费的数据契约：`batch_result.summary`、`hourly_details`、`economy_v1_result`、`single_entity_economy_result`、`RecommendationPortfolio`、`StudyResult`。
- 在 UI 文档里明确：mock 只允许出现在 `docs/ui/` 原型，不得进入正式 Streamlit 计算链路。

验收：

- 任意 UI PR 都能说明是否触及底层口径。
- 推荐页、图表页、导出页的真实字段来源可追踪到现有结果对象。

## Phase 1. Workbench Shell Cleanup

目标：保留六页工作流，但让导航、状态条和页面任务分工更清楚。

改造点：

- 左侧只做流程导航和最少状态，不再重复顶部所有状态。
- 顶部状态条只显示项目状态、当前模块、方案池、数据时间、报告方案。
- 页面内新增任务状态带：前置条件、当前可做动作、下一步。
- 修复窄屏遮挡：小屏时侧边栏折叠为顶部流程选择或抽屉，不覆盖主内容。

涉及文件：

- `src/green_direct/ui/app.py` 中工作台 CSS、导航和状态条函数。

验收：

- 390px 宽度下不遮挡主内容。
- 页面切换不触发 `workflow_page` session 错误。
- 顶部状态条和左侧状态不重复读同一信息。

## Phase 2. Simulation Page As Input Diagnostics

目标：把“方案仿真”改成输入诊断和候选池任务台。

改造点：

- 左列改成曲线诊断卡：负荷、光伏、风电、下网电价曲线的行数、时间范围、单位、异常点。
- 中列改成候选方案池摘要：容量范围、步长、候选数量、是否包含无储能。
- 右列改成政策与电网约束摘要：自发自用率下限、绿电占比下限、上网比例上限、交换功率限制。
- Demo 入口明确标注“使用内置示例，不覆盖正式上传文件；会清空旧经济结果”。

验收：

- 未上传数据时，页面展示缺失项清单，而不是空白上传控件。
- Demo 生成后清楚显示 27 个方案、达标数量和下一步经济测算入口。
- 不默认展示全量枚举大表。

## Phase 3. Economy Page Task Split

目标：让经济性测算成为“少量核心输入 + 高级参数复核 + 结果回馈”的工作台。

改造点：

- 首屏只保留基础经济参数、关键价格、最低可接受 FIRR、主 CTA。
- 把 Year 0 投资、运行费用、储能更换、收入税金、电费清单组价、价格曲线分别做折叠组。
- 计算完成后在参数区上方显示结果摘要：可排序席位、领先方案、缺失字段、是否需要重新计算。
- 当用户改动参数后显示“结果已过期，请重新计算”。

验收：

- `计算经济性 V1` 按钮在首屏可见。
- 经济计算完成后，推荐页和导出页状态立即变为可查看。
- 常用经济输入不藏在单一推荐视角的高级设置里。

## Phase 4. Recommendation Decision Page

目标：推荐页只帮助决策，不承担当页图表复核。

改造点：

- 推荐卡片结构固定为：席位标签、`scenario_id`、容量配置、关键技术指标、关键经济指标、推荐理由、风险。
- 同一方案命中多个席位时合并标签，不重复卡片。
- 未实现或不可排序席位显示 pending/no-candidate 卡片，而不是消失。
- 推荐理由支持展开；风险分级使用统一状态组件。
- 明细表默认折叠，只用于审计和复核。

验收：

- 推荐页不默认展示全量枚举大表。
- 推荐卡片可解释“为什么是它”，并能链接到图表复核和导出。
- 没有经济性结果时，页面明确说明缺什么、下一步去哪。

## Phase 5. Chart Review Workspace

目标：图表页只围绕推荐组合和用户指定方案进行复核。

改造点：

- 顶部保留方案组合选择：推荐方案 + 用户钉选方案。
- 图表分组改为：
  - 指标对比：绿电占比、自发自用率、弃电率、上网比例。
  - 配置对比：光、风、储功率、储能容量。
  - 典型日：24H 源网荷储曲线。
  - 关键日：高弃电、高下网、高上网等极端日。
  - 能量流：年度或月度来源去向。
- 每张图必须写清楚标题、单位、图例和回答的问题。

验收：

- 图表默认只使用推荐组合和用户钉选方案。
- 全量枚举只出现在高级复核或导出。
- 图表不重新调度、不平滑、不改变逐小时台账。

## Phase 6. Delivery Center

目标：下载页改成交付中心。

改造点：

- 顶部选择默认报告方案，并显示是否来自推荐组合。
- 分成四个交付包：
  - 技术包：方案汇总、所选方案逐小时 CSV、批量技术结果包。
  - 经济包：电源侧经济性、同一主体经济性、年度现金流。
  - 图表包：当前方案图表 HTML ZIP、推荐组合对比图。
  - 报告包：简版 Markdown、推荐组合 Excel。
- 每个包显示可用、待测算、需准备、暂未实现。

验收：

- 下载按钮不散落在仿真、经济、推荐页。
- 默认报告方案选择正确。
- 缺少经济结果或推荐输入时，导出页显示原因，不生成伪结果。

## Phase 7. Component Extraction

目标：在不大迁移的前提下，逐步降低 `app.py` 的 UI 复杂度。

建议拆分：

- `ui/state.py`：工作流和 session state 适配。
- `ui/components/status.py`：顶部状态条、左侧状态、任务状态带。
- `ui/components/cards.py`：指标卡、推荐卡、交付卡。
- `ui/pages/simulation.py`
- `ui/pages/economy.py`
- `ui/pages/recommendation.py`
- `ui/pages/charts.py`
- `ui/pages/exports.py`

注意：

- 先搬 UI 渲染函数，不搬计算函数。
- 保留现有 tests 通过。
- 每次只拆一个页面，避免大迁移。
