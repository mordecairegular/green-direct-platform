## 我建议你把这张图转成一份“UI 规则”

你可以在项目里加一个 `UI_SPEC.md`，专门固化风格。内容可以这样写：

```md
# UI_SPEC.md

## 1. UI 风格定位

本项目是绿电直连 / 微电网方案测算平台，面向工程技术人员、项目经理、投资测算人员和方案评审人员。

界面风格应为：
- 工程软件
- 数据分析后台
- 方案决策平台
- 专业、克制、可信、清晰

不得设计成：
- 营销官网
- 炫酷大屏
- 纯 demo 页面
- 花哨动画页面

## 2. 参考图说明

参考图路径：

docs/ui/reference-dashboard.png

该图仅作为布局和风格参考，不作为业务字段、计算逻辑或数据口径参考。

可借鉴：
- 左侧导航 + 顶部状态栏 + 主内容区
- 推荐方案卡片
- 多方案指标对比图
- 单方案典型日曲线图
- 下载和报告生成区
- 底部状态提示

不可照抄：
- 图中的具体方案编号
- 图中的 FIRR 指标
- 图中的收益口径
- 图中的示例数据
- 图中的业务文案

## 3. 页面信息层级

推荐页面顺序：

1. 顶部状态栏
   - 项目名称
   - 当前模块
   - 数据时间范围
   - 计算状态
   - 当前用户

2. 推荐方案区
   - 推荐方案数量
   - 推荐理由
   - 关键配置
   - 核心指标
   - 风险提示

3. 图表总览区
   - 多方案关键指标对比
   - 典型日运行曲线
   - 必要时增加年度电量结构图、储能运行统计图

4. 下载与报告区
   - 逐小时数据下载
   - 图表下载
   - 报告生成

5. 底部状态栏
   - 当前选中方案
   - 数据来源
   - 版本号
   - 帮助入口

## 4. 推荐方案卡片规范

每张方案卡片应包含：

- 排名编号
- 推荐标签
- 方案编号
- 风 / 光 / 储容量配置
- 绿电占比
- 自发自用率
- 弃电率
- 余电上网比例
- 经济性或节费指标
- 风险提示

卡片不应过度拥挤。指标过多时，只展示 4—6 个核心指标，其余放入详情页。

## 5. 图表规范

所有图表必须包含：

- 标题
- 单位
- 图例
- 横轴含义
- 纵轴含义
- 数据来源或当前选中方案

图表不得只为了好看而存在，必须回答一个明确问题。

例如：

- 多方案关键指标对比图：回答“哪个方案综合表现更好？”
- 典型日运行曲线图：回答“该方案一天内源荷储网如何协同？”
- 年度电量结构图：回答“全年电量由哪些部分构成？”
- 储能 SOC 曲线图：回答“储能是否合理运行？”

## 6. 颜色和视觉规范

颜色应克制、统一。

建议：
- 主色：蓝色或蓝绿色
- 成功状态：绿色
- 警告状态：橙色
- 风险状态：红色
- 背景：浅灰或白色
- 侧边栏：深蓝

禁止：
- 大面积渐变
- 霓虹色
- 随机颜色
- 过多阴影
- 过多动画
- 每个模块一套风格

## 7. 代码约束

UI 重构不得影响：

- 核心计算逻辑
- 调度算法
- 经济性计算
- 数据字段含义
- 导入导出格式
- 测试用例
- 既有业务流程

如需新增 mock 数据，必须隔离在 demo 或 story 文件中，不得污染真实计算链路。
```

## 你和 Codex 交互时最重要的一句话

你要反复强调这句话：
