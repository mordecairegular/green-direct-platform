# First Prompt For ChatGPT Project

我正在开发一个新能源 / 绿电直连 / 微电网规划测算平台。请你作为资深产品经理 + UI/UX 设计顾问 + Streamlit 应用审查专家，基于本 Project 中的背景文档、截图、代码/仓库信息，帮我继续审查并打磨 UI 和交互逻辑。

项目仓库：

```text
https://github.com/mordecairegular/green-direct-platform
```

请优先查看 `codex/UI` 分支；如果 GitHub connector 看不到该分支，请以我上传的 Markdown、截图和代码片段为准。

请注意：

1. 不要泛泛说“更现代、更美观”。
2. 必须结合业务功能、用户操作流程、指标阅读顺序来提建议。
3. 页面首先要清晰、可靠、专业，不追求花哨。
4. 不要修改核心调度/仿真/经济计算口径；可以建议 UI 展示层、状态流、组件组织、字段命名、图表表达和导出体验。
5. 如果某个建议需要底层服务字段支持，请明确标注为“展示层可做”还是“需要服务层新增字段，但不改变核心算法”。
6. 输出必须能交给 Codex 继续落地。
7. 有些功能已经在 2026-06-08/09 的 UI 中初步落地，请审查它们是否足够清楚，而不是重复要求“从零新增”。

请重点审查这些问题：

## A. 01 欢迎页 / 项目启动页

- 现在的欢迎页是否有必要？
- 类似这种专业网页平台的欢迎页应该承担什么任务？
- 如果保留，它应该显示哪些信息：项目状态、数据准备度、工作流进度、最近一次结果、关键风险、下一步行动？
- 如果不保留，是否应改成“项目启动台 / 数据准备台”？

## B. 02 方案仿真

- 当前已经有“容量范围遍历”和“指定单方案”两个入口；它们的关系、默认值、校验提示是否清楚？
- 当前批量上传入口已经能识别负荷/PV/风电/下网电价曲线；还应如何让“技术曲线”和“经济价格曲线”的边界更清楚？
- 导入曲线区域是否应该比候选池和政策参数区域更紧凑、更像输入清单？
- 输入诊断应该如何展示文件识别、小时数、价格曲线状态、缺失列、警告和后续影响？
- 是否已经充分表达“枚举只是内部候选方案生成，不是最终主结果”？

## C. 03 经济测算

- 当前已经展示绿电前/绿电后负荷到户综合价；它应该放在哪里最自然？
- 方案卡片里应该怎样同时展示：
  - 接入绿电前到户综合单价；
  - 接入绿电后到户综合单价；
  - 差值；
  - 绿电占比；
  - 绿电结算价格；
  - 下网加权平均电价；
  - 下网比例？
- 固定价格模式和小时价格曲线模式如何在 UI 上区分，避免用户误解？
- 经济性计算完成后，页面应该如何反馈“推荐席位现在是否可排序、是否有 pending/no-candidate 席位、是否需要重算”？

## D. 04 方案推荐

- 推荐页应该只做“决策”，还是保留部分图表？
- 推荐卡的字段顺序、标签、风险说明、席位合并应该怎么设计？
- 默认推荐席位：同一主体 FIRR 最优、电源侧 FIRR 最优、负荷侧可成交收益最优、工程代表方案。页面如何让用户理解这些席位的区别？
- 如果某个席位待排序或无候选，应该怎样展示，避免用户误以为系统漏掉了结果？

## E. 05 图表概览

- 多方案关键指标对比除了柱状图，是否更适合：
  - 子弹图 / 目标线图，表达政策底线和余量；
  - 点图 / 坡度图，表达方案差异；
  - 热力矩阵，表达指标是否达标？
- 当前政策底线余量矩阵已经加入弃电率，但弃电率不是政策硬阈值，只作为“低优运行指标”复核；这种表达是否清楚？
- 当前名称是“容量配置结构矩阵”，请判断是否比“容量配置指纹矩阵”更合适，或给出更好的中文命名。
- 容量配置对比有没有比普通柱状图更好的表达？
- 典型日、能量流向、完整图表复核是否应该隐藏在高级区域？如果不隐藏，页面层级怎么重排？
- 默认应展示推荐组合中的方案，但也允许从全部已计算方案中切换。这个选择器和方案卡应该怎么设计？
- 当前图表区域的推荐方案按钮已经能切换详细图表；请审查这个交互是否足够明显，是否还需要状态反馈或更好的布局。

## F. 06 导出中心

- 导出页如何改成“交付中心”，让报告方案选择、技术包、经济表、图表包、简版报告有明确结构？
- 默认报告方案应该如何选择？是否跟推荐组合绑定？
- 各交付包应该怎样显示可用、待测算、需准备、暂未实现？

## G. 上线和性能准备

- 未来网站上线，当前 Streamlit UI 哪些地方需要提前做基础设计？
- 遍历计算慢，UI 上如何避免用户误以为卡死？是否需要后台任务、缓存、并行计算提示、进度拆分？
- 并行计算如果作为后续代码任务，应如何界定范围，避免改核心算法？
